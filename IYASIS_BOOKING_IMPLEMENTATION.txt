## 目的
既存サイト https://toyotsuspa-coder.github.io/iyashiHP/ に、癒sis専用予約画面を実装する。

お客様の操作:
コース選択 → 日付選択 → Squareの実際の空き時間 → 名前/電話/メール → 予約確定 → Squareカレンダー登録

予約台帳はSquareを継続利用する。

## 必須UI
- モバイルファースト
- 色: 背景 #f7f2ec / 文字 #433b36 / アクセント #806c5d
- 上部に「コース / 日時 / お客様情報」の3ステップ
- 豊津駅徒歩30秒 / 完全個室 / 着替え不要 を自然に表示

コース:
1. 初回ドライヘッドスパ45分 / 4,000円 / 「初めての方におすすめ」
2. ドライヘッドスパ60分 / 6,200円 / 「定番」
3. 足つぼ＋ドライヘッドスパ90分 / 8,200円 / 「人気No.1」

※本番ではSquare Catalogの名称・金額を正とする。

日時:
- 7日単位
- 過去日時は出さない
- Square Search Availability APIの実空き枠だけ表示
- Asia/Tokyo
- 空きなし表示あり
- スタッフ指名なし。「空いているスタッフなら誰でも」で開始

顧客情報:
- 名前 必須
- 電話 必須
- メール 任意。ただしSquare仕様上必要なら必須に変更可
- 選択コース/日時/価格の確認表示
- 送信中はボタンdisabled
- Square API成功後だけ完了画面を表示
- 失敗時は適切なエラー表示

## 構成
GitHub Pages フロント
  ↓ HTTPS fetch
Cloudflare Worker: workers/iyasis-booking-api/
  ↓ server-side
Square APIs

Cloudflare Workerに実装:
- GET /api/services
- POST /api/availability
- POST /api/bookings

利用するSquare API:
- Bookings API
- Catalog API
- Locations API
- Customers API
- Team API（必要な場合）

まず無料プランで利用できるbuyer-level Bookings APIを優先し、seller-level前提にはしない。

## /api/services
Square Catalogの予約可能Service Variationとフロント表示用serviceKeyを対応させる。
秘密情報は返さない。

例:
{"services":[{"key":"trial45","name":"初回ドライヘッドスパ 45分","price":4000,"duration":45,"serviceVariationId":"..."}]}

## /api/availability
request:
{"serviceKey":"trial45","date":"2026-11-21"}

処理:
1. serviceKeyをサーバ側のservice_variation_idへ変換
2. Square POST /v2/bookings/availability/search
3. location_idとservice_variation_idを利用
4. 必要ならteam_member_idを利用
5. Asia/Tokyoの日付範囲で検索
6. 必要な空き枠データだけ返却

例:
{"slots":[{"startAt":"2026-11-21T10:00:00+09:00","label":"10:00","teamMemberId":"..."}]}

## /api/bookings
request:
{"serviceKey":"trial45","startAt":"2026-11-21T10:00:00+09:00","teamMemberId":"...","name":"...","phone":"...","email":"..."}

処理:
1. 入力検証
2. 予約直前にSquare空き枠を再確認
3. Customers APIで顧客検索または作成
4. Bookings APIで予約作成
5. idempotency_keyで二重送信防止
6. API成功時だけok:trueを返す

エラー:
- 枠が埋まった: 409
- 入力不備: 400
- Square/Worker障害: 500または502

## セキュリティ絶対条件
- Square Access TokenをHTML/JS/GitHub/コミット履歴へ絶対に保存しない
- Cloudflare Worker Secret SQUARE_ACCESS_TOKENからのみ取得
- .env/.dev.varsは.gitignore
- Production CORSは https://toyotsuspa-coder.github.io のみに制限
- 入力検証
- idempotency key
- 必要に応じて簡易レート制限/bot対策
- 個人情報をGA4へ送らない

## 未設定値
以下は捏造しない:
- LOCATION_ID
- service_variation_id
- team_member_id
- Sandbox Access Token
- Production Access Token
- Square API version

コード内は明確なプレースホルダーまたはWorker Secret/環境変数参照にする。
SETUP.mdに取得場所と設定手順を書く。

## Sandbox実装
1. Square Sandbox前提でWorker実装
2. /api/services
3. /api/availability
4. /api/bookings
5. フロントから接続
6. Square Sandboxの実空き枠が表示される
7. テスト予約がSandbox Squareカレンダーへ作成される

Productionへの切替は今回実施しない。

## 技術上の注意
- mockAvailabilityや固定TIMESは最終実装では使わない
- JST日付をtoISOString()だけで作ってUTC日付ずれを起こさない
- API空き枠取得中にもloading表示
- dateOffset変更時のselectedDate整合性を保つ
- キャンセル/変更機能は初版では作らない。既存Square/電話/LINEへ案内
- 決済機能は今回作り替えない
- 既存サイトの他ページを壊さない
