# ブログ運用手順

## 記事を投稿する

1. `data/blog-posts.json` に記事を1件追加する。公開の明示依頼がない場合は `status` を `draft` にする。
2. 記事内容、関連記事、表現ルール、医療機関への案内を確認する。
3. 次のコマンドを実行する。

```powershell
python tools/generate-blog.py
python tools/validate-blog.py
```

検証に通っても、依頼がローカル作業のみの場合は `git add`、commit、push、デプロイを行いません。公開サイトへの反映を完了したと報告するのは、実際に公開・デプロイを許可され、反映を確認した場合だけです。

`published` の記事は新規HTML、`blog.html`、`sitemap.xml` に反映されます。`planned` と `draft` は一覧とsitemapに含まれませんが、現行の `tools/generate-blog.py` はdraft用HTMLもリポジトリ直下に生成します。したがって、draft HTMLをデプロイすると、一覧に載らなくてもURL直打ちで閲覧される可能性があります。ローカル限定のdraftはpush・デプロイしないでください。URLからの閲覧も防ぐ必要がある場合は、draft HTMLを公開対象外へ分離する生成方式を先に実装してください。

`sourceFile` を持つ既存記事は、本文を再生成せず、slugと公開URLを保持します。既存記事の更新を依頼された場合は、変更対象と許可範囲を確認し、依頼されていない本文やページは変更しません。

## 記事データの書き方

新規記事では `id`、`slug`、`title`、`description`、`category`、`primaryIntent`、`datePublished`、`dateModified`、`authorName`、`excerpt`、`intro`、`keyPoints`、`sections`、`relatedPosts`、`cta`、`status` を入力します。記事全体は、読者に話しかけるような親しみやすい口語の敬体にします。`excerpt` は一覧のタイトル下に表示する自然で簡潔な紹介文にし、「〜をまとめます」などの定型的・機械的な言い回しや、タイトルと重複するキーワードの羅列を避けます。`intro` は記事冒頭でテーマと扱う内容を自然に案内し、excerptと同じ文を繰り返しません。記事ページではカテゴリ表示の下に一度だけ掲載し、本文の先頭では繰り返しません。`keyPoints` は記事の要点を3〜5個の短い箇条書きにし、堅い説明調を避けたうえで、各項目を名詞句などの体言止めで終えます。記事ページでは「ポイント」の見出しの下に箇条書きで表示します。本文、まとめ、FAQ、CTAも同じ口調に揃えます。`sections` は次の形式です。

```json
{
  "heading": "見出し",
  "paragraphs": ["本文の段落1", "本文の段落2"]
}
```

医療行為や効果を断定せず、強い症状や長引く症状がある場合は医療機関への相談を案内してください。画像は実在確認できた場合だけデータへ追加します。

## 新規記事作成プロンプト

次のテンプレートを使い、企画IDとdraft状態を依頼ごとに指定します。

```text
data/blog-ideas.json から企画ID「○○○○」を選び、記事データを data/blog-posts.json に draft で追加してください。

【記事内容のルール】
- 記事テーマに関する一般的で有用な情報は、検索ユーザーの疑問に答えるために必要な範囲で記載してよい
- 癒sis固有の情報（店舗情報・施術内容・スタッフ情報・資格・実績・経験・口コミ等）は、サイト内で確認できる情報だけを使い、推測・創作しない
- 一般情報と癒sis固有情報を混同しない
- 記事タイトルの検索意図に対して、具体的で役立つ回答を含める
- 既存記事と内容・検索意図が大きく重複する記事は作らない
- 記事全体を、読者に話しかけるような親しみやすい口語の敬体にする。堅い説明調や不自然な定型文を避け、内容に合った自然な言葉を使う
- excerptはブログ一覧のタイトル下に表示する自然で簡潔な紹介文にする。キーワード列挙や「〜をまとめます」などの機械的な説明調を避け、記事で得られる内容を日常的な日本語で伝える
- introは記事ページ冒頭の導入として自然な文章にする。excerptと同じ文を繰り返さず、読者の疑問に触れてから記事内容を案内する
- introは記事ページのカテゴリ表示の下に一度だけ表示し、本文の先頭や他の箇所に同じ文章を重複して書かない
- keyPointsに記事の要点を3〜5項目で設定する。堅く見えない短い表現にし、各項目は名詞句などの体言止めで終える。ページでは「ポイント」の見出しの下に箇条書きで表示する
- 癒sis独自の見解を伝える項目の見出しは、必ず「癒sisからのアドバイス」と表記する
- 本文、まとめ、FAQ、CTAも記事全体と同じ親しみやすい口語に揃える

【表現ルール】
- 「治る」「改善する」「効く」「予防できる」など、症状や健康状態への効果を断定する表現は使わない
- 「必ず」「絶対」「すぐに」などの保証・断定表現は使わない
- 「90%が〜」など、根拠のない割合・実績数字は使わない
- 医療行為・治療を行うような表現は使わない
- 「整える」は文脈に応じて使用してよいが、健康上の効果を保証する意味では使わない

【注意書き】
- 症状・身体の不調を扱う記事では、症状が長引く場合や強い場合は医療機関への相談を案内する
- 店舗情報・アクセス・予約・設備など、症状を扱わない記事では医療機関の注意書きを無理に入れない

【既存資産保護】
- 既存記事のslug、URL、本文は変更しない
- 既存の公開記事を勝手に再生成・上書きしない
- 既存ページのデザイン、GA4、予約導線、本体HPを変更しない
- generate-blog.pyが既存HTMLを書き換える場合は、実行前後の差分を確認し、今回必要な変更以外は残さない
- draft記事のHTMLも公開対象の場所に生成されることがある。draftはローカル作業に限定し、push・デプロイしない
- URL直打ちでも閲覧できない非公開draftが必要な場合は、draft HTMLを公開対象外へ分離する変更が必要であることを報告し、了承なしに公開・デプロイしない

【生成・検証】
- draftとして data/blog-posts.json に追加する
- generate-blog.py を実行する
- validate-blog.py を実行する
- draft記事が公開一覧・公開sitemapに追加されていないことを確認する
- draft記事のHTMLが公開対象の場所に生成されるか確認し、生成される場合はローカルにとどめる
- 既存公開記事数が変わっていないことを確認する
- 記事本文に禁止表現がないこと、既存記事と内容・検索意図が重複していないことを確認する
- excerptと記事本文が自然な口語で読みやすいこと、記事冒頭の「ポイント」が箇条書きで、各項目が体言止めになっていることを確認する
- validatorのエラーがあれば解消し、一覧のリンク数と公開記事数が一致することを確認する
- 記事全文を最終報告に掲載する
- ローカル作業を公開サイトへ反映済みと報告しない

【Git / 公開】
- git add、git commit、git pushを実行しない
- GitHubへの公開・デプロイは実行しない
- 作業はローカルでの編集・generate・validateまでとする
```

## 企画を管理する

公開前の候補は `data/blog-ideas.json` に登録します。企画には検索意図と差別化方針を必ず記載し、企画を追加しただけではHTMLを生成しません。

## 生成物の確認

生成後は、`sourceFile` を持つ既存記事のファイルが意図せず書き換わっていないこと、予約・電話・LINE・Instagramのリンクが維持されていること、sitemapのURLと一覧件数が一致することを確認してから公開します。
